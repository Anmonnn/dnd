# Архитектура

Интерактивная карта и энциклопедия D&D-мира. Статический сайт: после сборки — просто файлы,
хостится где угодно (GitHub Pages, Netlify, Cloudflare Pages), бэкенд не нужен.

## Главная идея: арт отдельно, данные отдельно

```
┌──────────────────────────────┐
│ Слои данных (векторные)      │  ← правятся постоянно: границы, города, дороги, подписи
│  features.geojson + лор .md  │     редактор прямо в браузере, файлы в git
├──────────────────────────────┤
│ Подложка (растровый арт)     │  ← меняется редко: source.png → тайлы
│  source.png → тайлы          │     можно заменить на апскейл, объекты не съедут
└──────────────────────────────┘
```

На картинке **ничего не рисуется** — ни границ, ни городов, ни подписей. Всё, что меняется
или должно реагировать на мышь, живёт в данных поверх картинки.

## Стек

| Что | Чем | Почему |
|---|---|---|
| Сборка, dev-сервер | Vite 8 | быстрый HMR, плагин мира встраивается в dev-сервер |
| UI | React 19 + TypeScript 7 | панели, поиск, карточки |
| Карта | Leaflet 1.9 (`CRS.Simple`-подобная своя CRS) | проверенный движок для «нереальных» карт, тайлы, слои |
| Редактор | Leaflet-Geoman (free) | рисование/правка полигонов, точек, линий, прилипание вершин |
| Состояние | zustand | |
| Контент | Markdown + YAML-фронтматтер, вики-ссылки `[[...]]` | можно писать в Obsidian |
| Валидация | zod | понятные ошибки в данных |
| Тайлы, маска суши | sharp (libvips), d3-contour | без Python/GDAL |

## Раскладка файлов

```
world/                          ← ВСЕ данные мира (можно открыть как хранилище Obsidian)
  world.json                    название мира, карта по умолчанию
  lore/                         статьи: один .md = одна сущность
    states/  settlements/  places/  landmarks/  regions/  characters/  factions/  notes/ …
    _templates/                 папки/файлы на «_» и «.» игнорируются
  maps/
    <mapId>/
      map.json                  метаданные карты
      source.png|jpg|webp|svg   арт-подложка (исходник)
      features.geojson          объекты на карте (пишет редактор)
      land.geojson              суша (генерирует `npm run maps:land`), опционально

public/generated/maps/<mapId>/  ← генерируется `npm run maps`, в git не хранится
  meta.json  preview.webp  {z}/{x}/{y}.webp

src/
  shared/                       изоморфный код (Node + браузер): типы, схемы, математика зума
  app/                          браузерное приложение
    map/                        движок карты на Leaflet
    components/                 UI
    editor/                     dev-редактор (в production-сборку не попадает)
tooling/
  world/                        компилятор контента + Vite-плагин + dev-API + `npm run check`
  maps/                         нарезка тайлов, извлечение маски суши
```

## Модель данных

**Сущность** — всё, о чём есть статья: государство, город, деревня, храм, персонаж, фракция.
Файл `world/lore/**/<id>.md`. id = фронтматтер `id` или slug имени файла
(«Государство-крепость.md» → `gosudarstvo-krepost`). Тип задаёт `kind` (реестр — `src/shared/kinds.ts`).

```markdown
---
name: Название города
kind: city                 # см. src/shared/kinds.ts
summary: Короткий текст для всплывающей карточки.
parent: soyuz-volnykh-gorodov # или "[[Союз вольных городов]]" — id, имя или алиас
map: id-karty-goroda       # подробная карта: world/maps/id-karty-goroda/
color: "#3f7d4e"           # области — цвет заливки; места — цвет значка (фракция, культура)
icon: "🏰"                  # необязательно: свой значок
aliases: [Другое название]
tags: [торговля]
visibility: public         # dm — видно только мастеру
facts:
  Население: 12 000
  Союз: "[[soyuz-volnykh-gorodov]]"
---
Текст статьи. Ссылки: [[gosudarstvo-krepost]], [[gosudarstvo-krepost|крепость]].

> [!dm] Секрет мастера
> Этот блок вырезается из сборки для игроков.
```

**Объект на карте** — геометрия в `world/maps/<mapId>/features.geojson`, связанная с сущностью
по `properties.entity`. Одна сущность может быть на нескольких картах. Объект без сущности —
просто подпись (`properties.name` + `properties.kind`): точка с типом водоёма или области
рисуется текстом без значка («Дальше живут драконы»).

```json
{ "type": "Feature", "id": "f-beskonechnaya-burya",
  "properties": { "entity": "beskonechnaya-burya" },
  "geometry": { "type": "Point", "coordinates": [790, 990] } }
```

Свойства объекта (`kind`, `name`, `detail`, `color`, `visibility`) переопределяют свойства сущности;
`labelAt: [x, y]` задаёт точку подписи области вместо автоматической. Линии типа `route` рисуются
пунктиром, линии остальных типов (стены, реки) — сплошными.

**Карта** — `world/maps/<mapId>/map.json`:

```json
{ "title": "Карта мира", "source": "source.png", "size": [1461, 1077],
  "background": "#0b2545", "entity": null, "parent": null, "clipAreasToLand": true }
```

Подробная карта города: `entity` = id города, `parent` = id карты мира. У сущности города
`map: <mapId>` — тогда в карточке появляется превью и кнопка «Открыть карту».

**Кружки (персонажи у мест)** — сущность с фронтматтером `location: <место>` получает на каждой
карте кружок `MapPin` у объекта этого места; если места на карте нет — у ближайшего предка по
`parent` (таверна → город → государство). Нарисованная на карте сама сущность кружка не получает.
Группа игроков (`kind: party`) — тот же кружок, но знамя: крупнее, в цвете `color`, с рядом аватаров участников
(персонажи с `parent: <группа>`); в ряду у места группы идут первыми.
У места: `residents` — кто к нему привязан. Кружок — это ещё и `locations` сущности,
поэтому «Показать на карте», поиск и адреса `#/e/<id>` работают для персонажей как для мест.

**Картинки** (`avatar`, `image`, `![[…]]` в тексте) ищутся рядом со статьёй → от `world/` → от `public/`
→ по имени файла во всём `world/`. Плагин делает копии `public/generated/media/<хеш>-s.webp`
(квадрат 128 px, кадрирование по «главному» на картинке) и `-m.webp` (до 800 px). Имя по хешу
содержимого: заменили картинку — сменился URL. В сборке остаются только копии, на которые ссылаются
данные этой сборки (портреты секретных персонажей в версию для игроков не попадают).

## Система координат и зум

- Координаты — «единицы карты»: `[x, y]`, x вправо, y **вниз**, (0,0) — левый верхний угол.
- Пространство `size` фиксируется в map.json при первой нарезке (= размер исходника в px)
  и больше не меняется. Замена арта на апскейл ×4 не сдвигает ни один объект.
- `zoomBase = ceil(log2(max(w, h) / 256))`; на зуме z одна единица = `2^(z − zoomBase)` px.
- Уровень тайлов z — картинка, отмасштабированная ровно до `size × 2^(z − zoomBase)`.
  Нативный максимум зависит от разрешения арта: исходник ×4 → `zoomBase + 2`.
- Leaflet: `LatLng(lat = y, lng = x)`, CRS = `CRS.Simple` с
  `transformation = new L.Transformation(2^−zoomBase, 0, 2^−zoomBase, 0)`.
  Поэтому `L.geoJSON` и `layer.toGeoJSON()` работают с файлами без пересчёта координат.
- Детализация: тип имеет `detail` 0/1/2; объект виден с зума `zoomBase + {−∞, −0.75, +0.25}`.

Вся математика — в `src/shared/zoom.ts` (общая для генератора тайлов и просмотрщика).

### Детальные врезки

`world/maps/<mapId>/insets/<insetId>/inset.json` — `{ title, bounds: [x, y, w, h], source?, showFrom?, feather? }`
+ `source.png` (детальный арт) + `reference.png`/`prompt.txt` (образец и промпт, их делает `npm run maps:inset`).

- Врезка режется на **той же** сетке тайлов, что и карта: уровень z — арт, отмасштабированный до
  `bounds × 2^(z − zoomBase)` и положенный в своё место пиксельной сетки мира (`tooling/maps/insets.ts`).
  В просмотрщике это обычный `L.tileLayer` с `bounds` в панели `insets` (над тайлами карты, под векторами).
- Уровни: от `insetMinZoom(showFrom)` до нативного уровня арта (`zoomBase + round(log2(px арта / ед. карты))`).
  `showFrom` по умолчанию — нативный максимум арта карты + 0.25: врезка проявляется (за `INSET_FADE` уровней),
  когда основной арт начинает мылиться. Предел зума карты растёт до нативного уровня самой детальной врезки + 1.
- Края растушёвываются в альфу (smoothstep на `feather` × меньшая сторона) — врезка ложится на арт карты без шва.
- Тайлы привязаны к `bounds`: если `inset.json` поменялся, а тайлы нет — компилятор прячет врезку и предупреждает.
  В dev новый арт карты или врезки и правка `inset.json` перенарезают карту автоматически (`buildMaps` из плагина).
- Клик по области разворачивает её на экран (`flyToBounds`); кнопка ⤢ возвращает всю карту.

## Конвейер сборки

1. `npm run maps` — для каждой карты с `source`: хеш исходника → если изменился, нарезка
   пирамиды тайлов WebP 256×256 (края прозрачные), превью, `meta.json`. Инкрементально.
2. Vite-плагин `tooling/world/vite-plugin.ts` при старте и при каждом изменении в `world/`
   компилирует мир (`compileWorld`): читает лор и карты, валидирует zod-схемами, рендерит
   Markdown (вики-ссылки, callout-блоки, секреты мастера), обрезает области по суше,
   считает точки подписей, связи (дети, обратные ссылки, расположения) → `virtual:world`.
3. В dev изменения долетают через HMR без перезагрузки страницы.
4. `npm run check` — та же компиляция в обоих режимах, отчёт об ошибках (для CI).

## Режимы: мастер и игроки

| Команда | Режим | Что видно |
|---|---|---|
| `npm run dev` | dm | всё + редактор + список проблем в данных |
| `npm run dev:public` | public | как увидят игроки, редактор выключен |
| `npm run build` → `dist/` | public | сайт для игроков |
| `npm run build:dm` → `dist-dm/` | dm | полная версия без редактора |

В режиме public сущности/объекты/карты с `visibility: dm` и блоки `> [!dm]`/`> [!secret]`
удаляются **на этапе сборки** — в браузер игрока они не попадают вообще.

## Dev-API редактора

Только `npm run dev` в режиме dm (контракт — `src/shared/api.ts`):

- `PUT /__world/maps/<mapId>/features` — перезаписать features.geojson;
- `POST /__world/lore` — создать заготовку статьи `world/lore/<папка типа>/<id>.md` (можно сразу с `location`);
- `PATCH /__world/lore/<id>` — поменять `location`/`avatar` во фронтматтере (остальной текст не трогается);
- `POST /__world/lore/<id>/avatar` — тело-картинка → `world/media/avatars/<id>.<ext>` + поле `avatar`.

Файлы пишутся на диск → наблюдатель плагина перекомпилирует мир → HMR.
В Vite есть `/__open-in-editor?file=<путь>` — открыть .md в VS Code из интерфейса.

## Соглашения

- Комментарии в коде — по-русски, коротко; идентификаторы — по-английски.
- `src/shared/*` не импортирует ни Node API, ни DOM.
- Новый тип сущности — только через `src/shared/kinds.ts`.
- Генерируемое (`public/generated`, `dist*`) в git не хранится.
